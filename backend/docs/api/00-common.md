# 공통 규칙·운영 요구사항

> 원문: [Notion](https://app.notion.com/p/40c23542cf8c81958c3df3b71c8cf631?pvs=204) · 내보낸 날짜: 2026-11-02 (KST)

## 적용 범위

모든 분류 API에 적용할 공통 계약과 별도 HTTP 엔드포인트가 필요 없는 SRS 요구사항을 기록한다. 분류별 문서의 세부 엔드포인트 표와 함께 읽는다. 실제 학교 SSO를 목업으로 대체한 것은 사용자가 승인한 범위 변경이다. 그 외 수치·경로·모델은 API 설계 초안이며 SRS 확정값과 구분한다.

## 공통 API 계약

### 요청·응답 형식

| 항목 | 계약 |
| --- | --- |
| Base path | /api/v1 |
| 식별자 | userId, itemId, reportId 등 내부 식별자는 UUID |
| 시간 | 날짜는 YYYY-MM-DD, 시각은 2026-11-02T15:00\:00+09\:00 |
| JSON | application/json. 204는 본문 없음. 사진 업로드만 multipart/form-data |
| 성공 응답 | 각 response model을 직접 반환. 공통 data wrapper 없음 |
| 언어 | Accept-Language: ko 또는 en. 미지원·누락은 ko. 선택 언어의 message·fieldErrors.message 및 Content-Language 반환 |

### 인증·권한·적용 범위

| 항목 | 계약 |
| --- | --- |
| 로그인 | 인증 문서의 KAIFIND\_SESSION 서버 세션 쿠키 |
| 쓰기 요청 | X-CSRF-Token 필수. 로그인 세션·역할·리소스 소유 관계는 서버에서 검사 |
| 역할 | MEMBER, ADMIN. GUEST는 유효한 로그인 세션이 없는 요청 |
| 요청 검증 | 정의되지 않은 필드 거부. null 허용 여부·PATCH 생략 규칙은 각 모델에 명시 |
| 상태 충돌 | 선행 상태 불일치·동시 변경 충돌은 409 |
| 숨김 | hidden은 POSTED/COLLECTED/EXPIRED 상태와 독립. 신고 후 숨김은 상태값을 바꾸지 않음 |

### 목록·페이지네이션

| 항목 | 계약 |
| --- | --- |
| 목록 기본값 | page=0, size=20, size 최댓값 100. 별도 명시가 없으면 생성시각 내림차순, 동률이면 ID로 고정 |
| 페이지네이션 지원 목록 응답 | items 배열과 page, size, totalElements, totalPages. 요소 모델은 각 문서에서 정의. 비페이지 목록인 목업 계정·공개 기준정보는 각 문서의 배열 응답 모델을 따른다. |

### 오류 처리

| 항목 | 계약 |
| --- | --- |
| 오류 응답 | 인증 문서의 ErrorResponse: code, message, fieldErrors |
| 검증 오류 | 필드명·안정적인 오류 코드·선택 언어 메시지를 제공하여 UI-2의 필드별 오류 표시 지원 |
| 권한 오류 | 미인증 401, 권한 부족 403. 존재 은닉이 필요한 비공개 리소스는 상세 명세에 따라 404 |

### 개인정보·접근 제어

| 항목 | 계약 |
| --- | --- |
| 개인정보 | DTO, 중첩 객체, 검색 인덱스, 로그, 알림, 사진 URL, 캐시까지 동일한 접근 제한 적용 |

### PageResponse 모델

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| items | 각 목록의 DTO 배열 | 예 | 결과가 없으면 빈 배열 |
| page | integer | 예 | 0부터 시작 |
| size | integer | 예 | 요청한 페이지 크기 |
| totalElements | integer, int64 | 예 | 조회 권한·필터 적용 후 전체 개수 |
| totalPages | integer | 예 | 결과가 없으면 0 |

서로 다른 도메인의 비공개 정보를 페이지 개수나 집계로 추정할 수 없도록 목록·집계에 같은 필터를 적용한다.

## 상태·후속 처리

| 사건 | 필수 후속 처리 |
| --- | --- |
| 습득물·분실 신고 생성 또는 수정 | FR-16의 정확한 조건으로 매칭 재평가. 신규 후보에 FR-17 알림 |
| 수거 완료 | 한 명의 수거자만 원자적으로 기록, 습득자 알림, 수거자의 관련 분실 신고 전부 종료 |
| 수거 취소 | POSTED 복귀. 이전에 삭제된 메시지·비공개 식별 정보는 복구하지 않음 |
| 30일 미수거 만료 | EXPIRED 변경·습득자 알림·메시지 삭제·감사 기록 |
| 분실 신고 종료 | 비공개 식별 정보 즉시 삭제. 이후 매칭 알림 중단 |
| 민감 물품 사진·보관 위치 조회 | 열람자·대상·시각 감사 기록. 다른 응답·이력·이미지 경로를 통한 우회 열람도 같은 규칙 적용 |
| 원본 레코드 삭제 | 연결된 매칭 후보 삭제. 별도 보존 의무가 있는 감사·수거 기록에는 불필요한 본문을 복사하지 않음 |

수거 전 소유권 승인, 운영자의 실물 보관·인계, 자동 이미지 인식, 네이티브 앱은 추가하지 않는다.

## 자동 작업과 외부 연동

아래 작업은 내부 스케줄러·이벤트 처리이며 회원이나 비회원이 호출하는 공개 API로 만들지 않는다.

| 작업 | SRS 요구사항 | 설계·검증 |
| --- | --- | --- |
| 습득물 만료 검사 | 매일 저사용 시간대, POSTED 30일 미수거 물품 만료 | 일일 작업이므로 정확히 30일 시각과 다음 검사 사이의 지연 가능성을 명시. 테스트 시 30일 경계·상태 경합 검증 |
| DB 백업 | 만료 검사 완료 후 별도 저장소에 백업 | 순서 보장. 백업 실패 감지와 복구 훈련 |
| 이메일 요약 | 매일 저녁 한 번 | 일일 한도 초과분 묶기, 중복 발송 방지. 시각·한도는 제안값으로 별도 표시 |
| 알림 재시도 | 실패한 알림 재전송 | REL-2. 영구 실패는 운영자가 식별 가능해야 하며 성공 처리로 버리지 않음 |
| 분실 신고 자동 종료 | 생성·연장 정책에 따른 30일 종료 | 비공개 식별 정보 즉시 삭제 |
| 보존 만료 정리 | 정해진 기간이 지난 데이터 삭제 | 메시지·비공개 식별 정보는 1년 작업을 기다리지 않고 종료 즉시 삭제 |
| 사진 저장 | 파일 스토리지 사용, EXIF GPS 제거 | GPS가 제거된 산출물만 영구 저장. 원본·썸네일·임시 파일에도 보관 정책 적용 |
| 사진 다운로드 | 유효기간 있는 링크 | 민감 사진은 짧은 유효기간 + 요청자 권한 검증. 정확한 수명은 SRS 미정 |
| 이메일 서비스 | 관련 페이지 링크 전송 | 민감 물품 사진·보관 위치를 이메일 본문·첨부에 포함하지 않음 |

자동 작업 시각·재시도 간격·분산 작업 방식·트랜잭션 구현은 설계 선택이다. 매칭 조건이나 보존 기간 같은 SRS 규칙을 변경하지 않는다.

## 보존과 삭제

| 데이터 | SRS 보존 정책 |
| --- | --- |
| 사용자 | 계정 활성 기간 동안 필요한 신원·역할·언어만 보관 |
| 습득물·사진·발견/보관 위치·변경 이력 | 물품 종료 후 1년 |
| 분실 신고 비공개 식별 정보 | 신고 종료 즉시 삭제 |
| 분실 신고의 나머지 정보 | 1년. 기산점은 SRS에 명확하지 않아 상세 설계 제안으로 표시 |
| 매칭 후보 | 연결된 어느 한쪽 레코드 삭제 시 삭제 |
| 수거 기록 | 1년 |
| 메시지 | 관련 물품이 COLLECTED 또는 EXPIRED가 되는 즉시 삭제 |
| 감사 기록 | 1년 |

개인정보를 일반 로그·알림 payload·검색 인덱스·캐시에 복제하여 삭제 규칙을 우회하지 않는다. 백업을 복원할 때도 종료·삭제 상태를 다시 적용한 후 서비스하여 삭제된 데이터를 재노출하지 않는다. 백업 보관 기간·암호화 키 폐기 등 구체적인 삭제 보장 방식은 운영 설계로 확정할 사항이며 이 문서만으로 구현 완료를 주장하지 않는다.

## 비기능 요구사항과 확인 기준

| ID | 요구사항 | API·운영·UI 확인 방법 |
| --- | --- | --- |
| PER-1 | 검색 95%는 2초 이내 결과 표시 | 실제 화면 기준 측정. 서버 응답시간만으로 충족 판정하지 않음 |
| PER-2 | 일반 모바일 환경에서 주요 콘텐츠 3초 이내 | 페이지 로딩 측정. 응답 크기·이미지 처리 검토 |
| PER-3 | 여러 사용자 동시 이용 시에도 PER-1 충족 | 동시 사용자 목표치는 SRS 미정. 부하 목표 확정 후 검증 |
| PER-4 | 사진 1장 업로드 5초 이내 | EXIF 제거 처리까지 포함한 대표 모바일 환경 측정 |
| REL-1 | DB 백업·장애 복구 | 별도 저장소와 복구 훈련 증거 |
| REL-2 | 알림 전송 실패 시 재시도 | 장애 주입 후 재전송 확인 |
| AVA-1 | 월 가용성 99% 이상 | 사전 공지 유지보수는 월 최대 4시간, KST 02:00\~06:00 범위. 가동 모니터 |
| SEC-1 | HTTPS, 미활동 세션 만료 | 브라우저·API HTTPS 확인, 세션 경계 테스트 |
| SEC-2 | 서버 인가, 민감 사진 단기 링크 | 역할·소유자 매트릭스, 링크 만료·다른 계정 사용·캐시 우회 확인 |
| SEC-3 | 다른 회원의 이메일·전화번호 비공개 | 모든 응답·메시지 상대방 모델 점검 |
| SEC-4 | 사진 EXIF GPS 제거 | 저장 산출물·썸네일 메타데이터 확인 |
| SEC-5 | 종료 시 개인정보 삭제, 불필요한 개인정보 미수집 | 신고·물품 종료 직후 API·DB·로그·캐시 확인 |
| UI-1 | 모바일·데스크톱에서 사용 가능 | 반응형 화면 점검 |
| UI-2 | 선택 언어로 필드 옆 오류 표시 | ErrorResponse와 폼 연결 확인 |
| UI-3 | 상태를 색상과 텍스트로 표시 | 상태 enum만 반환해도 UI에서 라벨을 별도로 표시 |
| USA-1 | 처음 사용자도 도움 없이 등록 | 사용자 사용성 테스트 |
| USA-2 | 모든 이미지에 대체 텍스트 | 사진 모델·폼·렌더링의 alt 확인. 민감정보 포함 대체 텍스트도 권한 적용 |
| USA-3 | 언제든 한국어·영어 전환 | 비회원 포함 UI 전환 및 언어 헤더 확인 |
| POR-2 | 데스크톱 주요 4개 브라우저 현·이전 버전, iOS Safari·Android Chrome | 브라우저 매트릭스 검증 |
| MNT-1 | 공유 버전관리 저장소와 구조 안내 | 저장소·가이드 확인 |
| POR-1 | 문서만으로 새 서버에 배포 가능 | 깨끗한 환경의 배포 재현 |

SRS Section 4에 따라 UC-1\~3, FR-5·16·20 수용 기준, 30일 이전 테스트 데이터, 권한·사진 링크 만료·EXIF 제거·DB 복구를 검증해야 한다. API 문서의 정합성 검토는 실행된 통합 테스트나 성능·보안 검증을 대체하지 않는다.

## SRS 미정 사항

| 미정 사항 | 현재 문서에서의 취급 |
| --- | --- |
| 세션 미활동 만료 | 인증 문서의 30분, 절대 12시간은 제안 |
| 민감 사진 링크 수명 | 사진 문서의 제안값으로 표시 |
| 이메일 일일 한도 | 알림 문서의 제안값으로 표시 |
| 동시 사용자 목표 | 미확정, 성능 충족을 주장하지 않음 |
| 직접 보관 물품 만료 정책 | FR-25의 30일 만료를 기본으로 유지. 예외 연장 정책은 확정 전 미적용 |
| 분쟁 중 메시지 보존 | SEC-5에 따라 종료 즉시 삭제를 유지. 분쟁 기간 보존은 SRS 변경 승인 전 미적용 |
